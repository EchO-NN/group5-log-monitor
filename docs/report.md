### 项目概述

我负责第五组演练中的日志监控工作，主要使用 Wazuh 收集和检测安全事件，使用 IRIS 管理告警、调查任务和证据。在此基础上，我编写了告警转发、案件管理和 AI 调查程序，使一轮演练从开始记录、集中采集到结束分析能够连续完成。

系统在 Case 2 中确认了备份账号从应用服务器访问 VM7、备份文件删除、应用主机高权限执行，以及数据库表结构变化引发的业务故障。本次又加入 VM9 性能接口，将资源指标与 Wazuh 日志按主机和时间关联，供调查 Agent 解释资源变化及业务影响。

## 一 系统结构与监控范围

日志采集以 VM8 为中心。Wazuh 负责解析日志和匹配规则，IRIS 保存案件。A 电脑运行远程采集和 AI 调查进程，VM9 提供性能指标与业务探测。各类记录保留自身时间，后续分析再按主机、账号、进程和对象进行关联。

| 位置 | 配置及作用 |
| --- | --- |
| VM2 网关 | 采集防火墙放行和拒绝日志，观察来源、目标和端口。 |
| VM3 员工终端 | Wazuh Agent、认证日志、Auditd 和用户目录访问记录。 |
| VM4 文件服务 | 共享目录操作审计；release_share 配置 Samba full_audit。 |
| VM5 应用服务 | SSH、sudo、程序执行、敏感配置访问、应用错误和日志文件操作。 |
| VM6 数据库 | 系统认证、审计和 MySQL 查询日志，提取数据库结构变化。 |
| VM7 备份服务 | SSH 与 SFTP、备份文件完整性、文件操作及校验结果。 |
| VM8 监控平台 | Wazuh、IRIS、告警队列、原始证据归档和案件状态。 |
| VM9 性能节点 | Prometheus 历史指标、订单和工单接口探测。 |

VM3 至 VM7 使用 Wazuh Agent，VM8 作为管理端也记录自身状态；VM2 使用 Syslog，VM9 通过补充采集进入案件调查。公开版的远程采集范围是 VM2 至 VM9。

监控内容覆盖账号访问、程序执行、关键文件变化、备份完整性、数据库操作、应用错误和资源状态。软件清单、漏洞匹配和配置检查用于掌握系统状态，事件调查则依靠当轮日志和实际查询结果。

## 二 Wazuh 采集与告警转发

Wazuh 从认证日志、journal、Auditd、应用日志和数据库日志中提取事件。Auditd 提供执行身份、程序、进程关系和文件对象；文件完整性监控记录新增、修改和删除；应用日志与业务探测用于说明操作造成的后果。

### 检测规则

| 规则或来源 | 配置内容 | 用途 |
| --- | --- | --- |
| Wazuh 内置规则 | SSH、sudo、文件变化等规则 | 识别常见安全事件 |
| 100510 等级 7 | 匹配 VM2 ACL DROP | 记录被访问控制拒绝的连接 |
| 100511 等级 12 | 匹配备份校验 FAILED | 记录备份不可读或校验失败 |
| 关键低等级白名单 | 指定账号认证、sudo、关键路径新增 | 保留调查所需的重要上下文 |

进入 IRIS 的主要阈值为 Wazuh 原始等级不低于 7。低等级白名单覆盖 dev_zhang、app_ops、bk_operator、db_admin 等实验账号，以及备份目录和应用配置等关键路径。等级映射采用固定规则，转发时不预先填写攻击阶段。

### 合并与保存

相同主机、规则和关键解码字段的事件，在五分钟窗口内合并展示。告警保留首次与末次时间、数量及成员记录，原始等级不变。普通采样与未选中的记录保留在证据区，供后续查询。

转发程序使用 SQLite 保存事件、投递状态、案件归属和重试信息。原始内容保存摘要与来源记录，IRIS 接收脱敏后的展示内容。投递和写入先核对已有对象，减少连接重试产生的重复记录。

| Alert 字段 | 展示内容 |
| --- | --- |
| 主机与时间 | 事件所属机器，首次和末次发生时间 |
| 规则与等级 | Wazuh 规则编号、描述及原始 level |
| 行为字段 | 来源和目标、账号、程序、文件路径等可用信息 |
| 证据信息 | 日志来源、合并数量、成员事件及脱敏摘录 |

这一步完成的是事实转发。关联判断放在结束后的调查中完成，便于在课堂展示时从告警继续打开证据，而不是仅展示一条结论。

## 三 IRIS AI 调查设计

我在 IRIS API 上封装了一组调查工具，由外部 Agent 调用。课堂环境通过 PackyAPI 使用 gpt-6.1-sol，推理强度为 xhigh。模型选择下一步操作，执行器完成实际查询或写入，再把结果返回模型。当前使用函数调用协议，未封装成标准 MCP 服务。

begin 创建独立 Case 并记录开始时间；finish 记录结束时间，等待在途日志后启动调查。模型取得本轮告警概览、主机角色、时间窗口和证据目录，先建立 Tasks，再围绕任务补查日志。预设十阶段流程没有作为本轮判断的输入。

| 工具 | 实际作用 |
| --- | --- |
| create_tasks update_task | 建立调查问题，更新已执行的核查结果。 |
| read_evidence | 读取告警及前序查询结果。 |
| query_host | 读取认证、审计、服务日志或当前备份清单。 |
| inspect_files | 只读查看目录、文件信息、文本和搜索结果。 |
| query_collected | 查询数据库、应用、业务探测和 VM9 性能证据。 |
| record_case finish_case | 分次写入案件区域，核对完成条件并结束研判。 |

每一步调用与结果都先保存，再交给下一轮模型请求。模型需要更多上下文时继续查询；已经得到的证据在后续步骤保留。审计每页返回 80 条，可持续续读。中途出现网络或接口故障时，根据保存的作业和回执继续。

### IRIS 中的最终内容

Summary 总结事件性质、手段、资产和影响。Timeline 按事件时间组织行为链，说明节点间的关联依据。Tasks 记录调查问题与核查结果。Notes 保存分析过程，Assets 说明相关机器，Evidence 分组引用真实告警和查询内容。

告警使用 A 编号，查询结果使用 E 编号。程序检查引用存在性、时间顺序和任务状态，并保护人工编辑过的内容。Timeline 区分因果、提供后续条件、活动延续和时间相邻，避免把同一时段的独立事件连成一条确定链路。

进度页面显示当前工具、操作目的、任务状态和最近实际动作。查询回执用于证明执行情况。AI 对主机的操作限制在只读工具内，案件写入限定于本轮 Case。

## 四 VM9 性能联合分析扩展

原接口只采集 VM3 CPU 和业务失败记录。本次新增 Prometheus 历史范围查询，采集器在 VM9 读取 query_range 接口，再通过原有管理通道将样本交给 VM8 保存。每 30 秒取一个时间点，单次最多回看两小时。

| 指标 | 分析用途 |
| --- | --- |
| CPU 使用率 | 观察程序执行附近的计算资源变化 |
| 内存使用率 | 观察进程和应用活动对应的内存压力 |
| 一分钟负载 | 补充 CPU 使用率之外的系统排队情况 |
| 磁盘使用率 | 观察文件增长与可用空间变化 |
| 磁盘读取与写入速率 | 观察归档、备份和数据库活动附近的 I/O |
| 网络接收与发送速率 | 观察访问和传输活动附近的流量变化 |
| 目标抓取状态 | 说明采样目标是否可达 |

CPU、磁盘和网络速率使用两分钟计算窗口。每个样本记录采集节点 sensor_host 和实际目标 target_host，避免把所有主机的指标都归到 VM9。未知实例、非有限数值和窗口外样本不会进入正常统计，空响应保留为无采样。

### 与 Wazuh 日志的关联

performance_metrics 按主机和指标统计样本数、最小值、最大值、平均值、峰值时间和末值。performance_correlations 查找 Wazuh 事件前后 120 秒内同一主机的指标，返回告警事件编号、指标摘要和时间关系。所有已保存样本参与统计，不只计算第一页。

Agent 得到关联结果后，可以继续查询同一时段的命令、认证、文件或应用日志。例如应用服务器在 sudo 记录附近出现 CPU 升高，下一步核对实际执行程序；若同时发生数据库错误和业务失败，再将这些结果写入时间线。

业务探测现在同时保存成功和失败，并记录 HTTP 状态与耗时，便于在故障后继续观察恢复。性能数据作为辅助证据，不改变 Wazuh 原始等级。此扩展已完成代码与本地测试，VM9 在线联调待节点恢复后执行。

## 五 Case 2 实际演练结果

2026 年 11 月 5 日的 Case 2 使用真实实验日志完成调查。以下时间均为北京时间。案件先从账号活动定位访问路径，再使用系统调用、数据库对象和业务结果确认影响。

| 时间 | 事件 | 主要证据 |
| --- | --- | --- |
| 03:26:48 | VM3 接受 dev_zhang 登录 | VM3 认证日志 |
| 03:27:31 | VM5 接受来自 VM3 的 app_ops 登录 | VM5 认证日志 |
| 03:27:33 | 原登录 UID 1001 的进程以 root 执行 | 审计 27775 |
| 03:27:40 | VM7 接受 VM5 来源 bk_operator 公钥认证 | E017 认证日志 |
| 03:27:41 | 备份归档被成功删除 | 审计 43543 E096 |
| 03:27:45 | 数据库收到两张业务表重命名 | E005 数据库日志 |
| 03:27:47 | 应用报告对应表不存在 | E006 应用日志 |
| 03:28:13 | 订单和工单探测失败 | E010 业务探测 |
| 03:28:45 | 数据库收到反向重命名 | 数据库日志 |
| 03:28:55 | 同名备份文件重新创建 | FIM 和审计 |

VM7 认证记录中的 Accepted publickey 证明 bk_operator 从 VM5 地址完成认证，随后启动 internal-sftp。审计事件 43543 将成功 unlink、UID、进程及目标归档路径直接绑定。会话与删除操作的关联得到时间和身份支持，人的归因仍需更完整的会话记录。

数据库表重命名后，应用对相同对象报告 1146 错误，独立业务探测随后失败。这组记录说明结构变化造成了业务影响。高权限执行已被审计确认，但它本身不足以确定具体 sudoedit 漏洞机制。

最终案件包含 14 个时间线节点、12 条关系、3 个调查任务、5 项资产、3 条笔记和 4 组证据。VM5 留存审计返回 5609 条，VM7 返回 419 条。06:06:43 的备份清单显示文件哈希符合基线；历史探测没有覆盖业务恢复后的成功结果。

## 七 部署操作与项目交付

项目使用 Python 标准库实现核心监控逻辑。公开版通过 SSH 别名连接各虚机，IRIS、Wazuh 页面地址和模型服务地址使用示例配置。实际 API 密钥放在仓库外的本地文件中，配置只保存文件路径。

```bash
git clone https://github.com/EchO-NN/group5-log-monitor.git
cd group5-log-monitor
make test
make demo
```

部署时先配置主机连接、IRIS 凭据与 CA，再安装 VM8 转发服务和 A 电脑上的采集及调查服务。VM9 恢复后，核对 Prometheus 实例地址与 TARGETS 映射，再采集一轮指标检查入库和查询。

```bash
./监控自动化.sh begin --label "第五组正式演练"
./监控自动化.sh status
./监控自动化.sh finish
watch -n 2 './监控自动化.sh ai'
```

课堂展示时，先在 Wazuh 中打开原始告警，说明主机、规则和时间；随后在 IRIS 中查看本轮 Case，依次展示 Summary、Timeline、Evidence 和 Tasks。以备份账号访问、文件删除及业务错误为例，可以从结论逐步追溯到具体日志。
