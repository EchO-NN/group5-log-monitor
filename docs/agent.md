# IRIS AI 调查机制

调查服务是自建工具调用 Agent。模型决定下一步，执行器实际调用主机查询或 IRIS API，再把执行结果交回模型。IRIS 负责案件管理，模型调用和进度控制由外部服务完成。当前接口是函数调用，不是标准 MCP 服务。

## 调查过程

`begin` 记录时间并创建 Case。演练期间，转发程序按固定规则生成 Alerts。`finish` 之后，Agent 得到本轮告警、时间窗口、主机角色和可用证据目录，先创建调查 Tasks，再选择查询工具。每一步先保存调用记录，再执行查询或写入；重试时核对回执和已有对象。

| 工具 | 作用 |
|---|---|
| create_tasks update_task | 建立调查问题，记录核查结果 |
| read_evidence | 阅读原始告警引用和实际查询结果 |
| query_host | 查询认证、审计、服务日志和备份清单 |
| inspect_files | 列目录、查询元数据、分页读取和搜索文件 |
| query_collected | 查询数据库变更、应用错误、业务探测、性能汇总及关联结果 |
| record_case | 分次写入 Notes Timeline Assets Evidence Summary |
| finish_case | 校验任务与证据覆盖后结束研判 |

模型不预先取得十阶段攻击流程。主机角色用于定位查询。读到脚本或历史报告时，其内容只提供线索，当轮日志负责证明实际行为。

## 案件内容

Summary 解释事件性质、手段和影响。Timeline 使用事件本身的时间，并说明节点间的关系。Tasks 记录已经核查的问题；完成表示调查动作完成。Notes 保存查询过程和判断理由。Assets 说明相关主机的作用。Evidence 引用告警与实际查询内容，附件由程序从保存的证据生成。

告警引用使用 A 编号，实际查询使用 E 编号。程序检查引用是否存在、时间顺序是否合理、前置节点是否形成循环，以及是否覆盖输入告警。因果判断仍需结合证据内容复核。

## VM9 联合分析

存在性能采样时，Agent 可以调用 `performance_metrics` 查看主机指标统计，再调用 `performance_correlations` 获取同机、前后 120 秒内的告警关联。模型据此选择是否继续读取认证、执行、文件或业务日志。

例如应用服务器在 sudo 告警附近出现 CPU 升高，Agent 可以继续核对同一时段执行的程序；若同时出现数据库错误和业务探测失败，再将资源变化与业务影响放到同一时间线上。输出分别保存各项事实及关联依据。

## 执行与进度

VM2 至 VM9 开放固定只读调查；本机仅开放项目目录。文件结果对常见凭据脱敏，管理密钥由执行器使用。IRIS 写入限定本轮 Case，已被人工编辑的内容触发冲突检查。

默认每轮最多 28 个模型步骤、10 次独立遥测查询和 250000 Token；审计续页不占独立查询名额，但计入步骤和用量。Case 2 曾按证据规模单独扩大预算，该设置没有改变其他案件默认值。

`./监控自动化.sh ai` 展示当前工具、简短目的、任务状态和最近实际动作。`pending` 表示待领取或重试，`running` 表示执行中，`done` 表示调查结束。持续返回内容会刷新空闲计时。原始内部推理不作为进度证明，实际工具回执用于复核工作。
